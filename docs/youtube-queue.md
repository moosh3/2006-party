# Individual YouTube videos in the show queue

Use **Manual** cue mode. Under **Add YouTube Video**, paste a video URL or its 11-character ID. **Check Video** is read-only: it checks title, finite duration, embedding permission and caption availability, and fills the duration/title when verified. **Add** saves it in the same media library as Mux; then queue it normally. **Add & Make Current** is an explicit broadcast change. YouTube playlists stay separate ambient sources, not queue cues.

The existing server clock owns both providers' queue transitions, pause/resume, hold, restart and new playback occurrence IDs. A late viewer joins at the shared current position, not the beginning. Player-ended events only refresh the clock; they cannot consume a queued item. Native YouTube seeking or pausing is corrected to the shared show state. Native volume and captions remain available.

## Captions and limitations

The embedded player requests captions **on by default** (`cc_load_policy=1`) and prefers English (`cc_lang_pref=en`). This is YouTube's documented default request, not a guarantee that a track exists or that every device honors it. Viewers can use native **CC** and language settings. We do not hide YouTube controls, branding, ads or restrictions, download videos, or synthesize absent tracks. [Official player parameters](https://developers.google.com/youtube/player_parameters).

With the server-only `YOUTUBE_API_KEY`, the official Data API supplies duration and its caption-availability flag. A positive flag is reported as available. A negative or missing flag means **captions unverified**, not necessarily absent: automatic captions can still appear in the player. This produces a warning and does not block checking or adding the video; the verified title/full duration still fill in. Confirm a usable track and visible subtitles in the embedded player before the show. Private, live/upcoming, age-restricted, unprocessed and non-embeddable videos, and invalid finite durations, remain rejected. Regional restrictions are flagged. If metadata verification is unavailable, an exact operator duration is mandatory and the UI explicitly marks captions and embed playback **unverified**; rehearse before using that fallback. [Official video metadata](https://developers.google.com/youtube/v3/docs/videos).

YouTube ads, buffering, keyframe seeking, regional blocking, changing ownership settings and viewer consent/privacy settings make it less predictable than Mux. An ad can interrupt a viewer even while the shared queue clock continues. Use a captioned Mux version for critical timed show segments. Muted autoplay is attempted; browsers may require **Join live show** or **Turn on sound**. Error messages and Retry are available for missing/private/blocked videos and failed embeds. [Official IFrame API](https://developers.google.com/youtube/iframe_api_reference).

YouTube's API duration is provider-reported and may differ slightly from the embedded media duration because of processing/encoding. The verified rehearsal video reported 1204 seconds through the production API, versus 1203.421 seconds in the actual player. This is another reason to use Mux when exact broadcast timing is critical.

This addition is for the manual queue. It does not add individual YouTube cues to the scheduled YAML rundown.
